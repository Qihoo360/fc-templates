/**
 * Defines the lifecycle states of a Task.
 */
export enum TaskState {
  /** The task has been submitted and is awaiting execution. */
  Submitted = "submitted",
  /** The agent is actively working on the task. */
  Working = "working",
  /** The task is paused and waiting for input from the user. */
  InputRequired = "input-required",
  /** The task has been successfully completed. */
  Completed = "completed",
  /** The task has been canceled by the user. */
  Canceled = "canceled",
  /** The task failed due to an error during execution. */
  Failed = "failed",
  /** The task was rejected by the agent and was not started. */
  Rejected = "rejected",
  /** The task requires authentication to proceed. */
  AuthRequired = "auth-required",
  /** The task is in an unknown or indeterminate state. */
  Unknown = "unknown",

rejected：
能力不匹配：请求功能、输入输出格式超出 agent 声明的技能 / 扩展范围，或与 agent 核心定位冲突。
认证授权失败：缺少合规认证凭证、权限不足（含技能级权限要求），或 TLS 证书校验未通过。
协议 / 参数违规：缺少必填字段、参数格式违法协议规范、使用未声明的传输协议，或数据结构不符合核心定义。
主动拒绝执行：任务违反安全策略 / 业务规则、存在固有无法完成的问题，或 agent 资源不足无法接收新任务。


input_required:
根据 A2A 协议 v0.3.0 规范，“agent to agent input_required”（需补充输入）返回的核心条件是 任务执行中断，需客户端提供关键信息才能继续推进，仅在 TaskState.InputRequired 状态下触发，具体场景如下：
1. 任务核心信息缺失或不明确
初始请求未包含完成任务的必填数据（如路由规划任务缺少起点 / 终点、文件处理任务未提供文件引用）。
请求信息模糊或存在歧义（如 “生成报告” 未指定报告类型、时间范围，agent 无法自主决策）。
客户端提供的 Parts 内容不完整（如文本片段缺失、结构化数据字段遗漏），导致任务无法推进。
2. 任务执行过程中需要用户确认
任务涉及多选项决策（如 “优先推荐高速路线还是最短路线”），agent 无预设规则，需客户端明确偏好。
操作可能产生潜在影响（如覆盖已有数据、超出免费额度），需客户端确认授权后再执行。
任务参数存在冲突（如 “要求最快送达且不产生运费”），需客户端协调调整需求。
3. 数据格式或内容校验不通过，需修正补充
客户端提供的数据格式合法，但内容无效（如手机号格式正确但无法接通、日期超出有效范围）。
输入内容不符合任务要求的约束条件（如字数超限、文件大小超标、关键词缺失）。
结构化数据校验失败（如数值字段为非数字、枚举字段值不在允许列表内）。

auth_required:
根据 A2A 协议 v0.3.0 规范，“agent to agent auth_required”（需补充认证）返回的核心条件是 任务执行过程中需要额外身份验证才能继续，仅在 TaskState.AuthRequired 状态下触发，具体场景如下：
1. 任务执行中需访问第三方资源的认证
agent 执行任务时需调用外部系统或工具（如第三方 API、受限数据接口），而该资源要求独立于 A2A 基础认证的额外凭证。
额外认证需求需通过 TaskStatus.message 明确说明，可包含认证类型、所需凭证格式等信息（如 OAuth 2.0 二次授权、API 密钥补充）。
2. 基础认证过期或权限不足
客户端初始提供的认证凭证（如 OAuth 令牌）在任务执行过程中过期，且无法自动刷新。
任务执行中涉及的子操作需要更高权限（如从 “读取” 扩展到 “修改” 数据），当前凭证的权限范围不满足。
3. 动态触发的身份校验
任务执行过程中出现异常风险（如异地请求、敏感操作），agent 需客户端补充额外身份验证（如二次验证、验证码）以确认权限。
涉及多步骤协作的任务，后续步骤的资源访问需要新的认证上下文（如跨租户数据访问的临时授权）。

4.5. In-Task Authentication (Secondary Credentials)¶
If an agent, during the execution of a task, requires additional credentials for a different system or resource (e.g., to access a specific tool on behalf of the user that requires its own auth):

It SHOULD transition the A2A task to the auth-required state (see TaskState).
The accompanying TaskStatus.message (often a DataPart) SHOULD provide details about the required secondary authentication, potentially using an PushNotificationAuthenticationInfo-like structure to describe the need.
The A2A Client then obtains these new credentials out-of-band and provides them in a subsequent message/send or message/stream request.
 How these credentials are used (e.g., passed as data within the A2A message if the agent is proxying, or used by the client to interact directly with the secondary system) depends on the specific scenario.
